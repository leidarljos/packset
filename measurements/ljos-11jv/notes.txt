What a write spends dropping claims whose window has closed, once a workspace already holds 20,000 live claims.
The writer keeps the soonest `valid_to` in the workspace and walks the live set only once that stamp has passed.
Before that, every write walked every live claim under the lock. The walk is the snapshot stage: it runs before that stage is marked.

## Where these runs happened

Every run was one Kernel-based Virtual Machine guest: Intel(R) Xeon(R) Processor, family 6 model 207 stepping 2, 8 cores, one thread a core, 2400.000 MHz, BogoMIPS 4800.00, CPU only.
`/proc/cpuinfo` reports `cpu MHz` 2400.000 on every core. There is no `cpufreq` directory. The flags include `constant_tsc` and `tsc_known_freq`.
The guest ran Linux 6.12.94+ and rustc 1.97.1 (8bab26f4f 2026-07-14).
Tmpfs runs used `/dev/shm`, mounted `rw,nosuid,nodev`. `findmnt` also prints a second tmpfs on the same target, `rw,nosuid,nodev,noexec,relatime`, so each log header has that second line under the filesystem line.

The parent binary is `packsetd` 0.17.3 (e8e3513f), built from e8e3513fbd3a94faae2f39785dfba616bd1aec2d, the parent of c3f08fbcbb6097efa21f8536b8c1c56b203c0517.
The develop binary is `packsetd` 0.17.3 (3f9ba044), built from 3f9ba044fc6d4fdd77a9109a80525aaf12878464.
The lane binary is `packsetd` 0.17.3 (3f9ba044+), built from the sources in this commit while the tree was still dirty, which is why the version line carries the `+`.
All three were release builds. The probe starts each with `--no-embed`.

The raw logs are the `*.log` files under `walk/` and `cached/`. Each header names the draw, the start time, the binary, the seed, the kernel, the CPU and the filesystem.
`measurements/jo0g/summary.py` reports pooled writes and per-draw medians, each with its interquartile range.
Quartiles are `statistics.quantiles(n=4, method="inclusive")`. The median is the upper one, `xs[len//2]`.

## How a draw was made

One seed pack of 20,000 live lessons in the workspace `shared` was written by the parent binary.
The seed command was `python3 measurements/jo0g/drive.py seed /tmp/ljos11jv-bins/parent/packsetd /dev/shm/ljos11jv-seed/20000 20000 8791`, from 2026-11-03T12:13:21Z to 2026-11-03T12:24:17Z.
Every draw copied that pack and posted 48 new lessons into the copy, in a fresh `packsetd` process.
`PACKSET_LIVE_CAP` was 20,048, the default cap of 20,000 plus those 48, as `measurements/jo0g/drive.py` sets it.
Six draws of each condition, odd draws in the order of `conditions.txt` and even draws in reverse.
The walk session ran `measurements/jo0g/run.sh measurements/ljos-11jv/walk/conditions.txt 6` from 2026-11-03T12:24:54Z to 2026-11-03T12:25:19Z.
The cached session ran `measurements/jo0g/run.sh measurements/ljos-11jv/cached/conditions.txt 6` from 2026-11-03T12:30:15Z to 2026-11-03T12:30:53Z.
Every probe exited 0.

The first write of a process copies the live claims into the set index. That write is one of the 48. The median of those six first writes, snapshot then total, was 110.20 ms and 312.00 ms on the walk parent, 113.10 ms and 315.10 ms on the walk develop, 114.50 ms and 318.10 ms on the cached parent, 114.90 ms and 317.00 ms on the cached develop, and 111.60 ms and 325.90 ms on the lane writer. The medians below are of all 288 traced writes. That first write is the maximum, so it does not move the median.
